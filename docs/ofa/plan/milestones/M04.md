**Purpose:** pick providers by evidence; Hindi text handling · **Depends on:** M01 · **Files likely touched:** `api/ofa/voice_router.py`, `api/ofa/text/{hi_numbers,translit}.py`, `api/scripts/{bench_record,bench_voice}.py`, `docs/ofa/bench/refs.yaml`, `api/tests/ofa/test_{router,hi_numbers,translit}.py` · **Done when:** B2–B6 pass and results file committed.

Read: §4 (all); plan 03.

## Steps
1. **Hindi TTS check** (live, 2 calls): Deepgram `/v2/speak` with the Hindi voice `voice_for("hi")` currently uses + Gradium TTS with Hindi text. Non-empty, audibly Hindi (user confirms). Record in 03 conflict line via PLAN-DELTA.
2. `text/hi_numbers.py` + 60-case test (Devanagari + Roman; numbers, ordinals, dates "agle somvaar", times "saadhe paanch", "paune do", currency "do sau rupaye").
3. `text/translit.py` (indic-transliteration ITRANS→casual Roman map) + roundtrip/token-count tests; user pref `script`.
4. `scripts/bench_record.py`: prompts the user through `docs/ofa/bench/refs.yaml` (60 items: 20 EN, 20 HI, 20 Hinglish; incl. 10 dictation-with-pauses), records 16 kHz WAV to `_local/bench/audio/` (gitignored path outside repos). Consent prompt first.
5. `scripts/bench_voice.py`: offline replay of WAVs through Deepgram Flux multi, Deepgram Nova-3 multi, Gradium (EN set + Hinglish for evidence) → WER, critical-token accuracy, end-of-turn false cuts (dictation set), latency p50; TTS: 5 sentences per language per provider → user rates 1–5. Cost/min from provider pricing pages (record URL+date). Cache transcripts to `_local/bench/cache/` so reruns cost 0.
6. Write `docs/ofa/bench/results-<date>.md` (≤ 60 lines) and update `ROUTES` in `voice_router.py` from it. Ensure Gradium holds ≥ 1 role if it wins any; else document as EN fallback.
7. Degraded mode: if no Hindi TTS, router returns `(en_voice, degraded=True)` → session announces once.
8. Wire `script` pref + hi_numbers into transcript post-processing for commands (numbers normalized for engine) — dictation keeps verbatim words (M06).
