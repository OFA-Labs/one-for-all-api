**Purpose:** complex tasks with spoken plans and safe multi-destination output · **Depends on:** M07, M08 · **Files likely touched:** `api/ofa/{planner,workflow,artifacts}.py`, `api/tests/ofa/test_{planner,workflow}.py` · **Done when:** P1–P6, W1–W6 pass.

## Interfaces
```python
@dataclass(frozen=True)
class PlanStep: n: int; text: str; app: str; tier: int; destination: str | None
@dataclass(frozen=True)
class TaskPlan: id: str; steps: tuple[PlanStep, ...]; digest: str   # sha256 of canonical steps
@dataclass
class DestinationStatus: dest: str; account: str; status: Literal["pending","sent","failed","unknown"]; idem_key: str
```
## Steps
1. Complexity classifier (deterministic rules + engine hint) → `planner.build()` via engine `plan` tool → `TaskPlan`.
2. Spoken plan template (≤ 7 items; else screen + summary) → approval request kind `plan` (digest bound) → revise loop.
3. Executor walks steps; each Tier 2 step still asks (P6); material change detector (new dest / new tier-2 / scope) pauses and re-asks (P5); progress line per step or 10 s.
4. `artifacts.py`: temp store with sha256, typed; passed between steps by id.
5. `workflow.py`: per-destination status + idempotency keys persisted in `memory.db` (survives crash); retry only `failed`; `unknown` → verifier checks target (sent folder / channel last message / file exists) else ask.
6. Repo work read-only by default; untrusted code execution only in Windows Sandbox if enabled (`Get-WindowsOptionalFeature Containers-DisposableClientVM`), else refused and reported.
7. Final report template: each destination + status, spoken + on screen.
