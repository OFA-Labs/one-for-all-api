## Interfaces
```python
@dataclass
class Criterion: text: str; kind: Literal["text","number","date","location","bool"]; op: str | None; value: Any | None
@dataclass
class Goal: description: str; criteria: list[Criterion]; source: str; max_iterations: int = 50
@dataclass
class Candidate: ref: str; title: str; evidence: dict[str, str]; passes: dict[str, bool]
```
## Steps
1. Engine tool `start_goal(goal)` → `goal_loop.run()` drives harness observe/scroll/next-page itself; engine called per page to extract candidates + per-criterion pass/fail with quoted evidence.
2. Deterministic re-check for number/date/location criteria (parse evidence; engine claim overridden if parse disagrees).
3. Stop conditions + loop detector (observation hash ×3) + exhaustion (2 empty iterations) + epoch/stop interrupt.
4. Near-match reporting template; true matches announced and stored in `memory.context.last_results` with ordinal refs.
5. `memory.resolve(ref)`: "this/that/the second one/same person/usko/wahi" → candidates; role refs (manager, mom) from profile contacts (D1 labels); ambiguous → spoken question.
6. Learned mappings: only saved after user confirms ("Should I remember that 'manager' means Priya?" — names come from the user, never hardcoded); CLI view/edit/delete.
