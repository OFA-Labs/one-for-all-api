## Ordered implementation

1. **CP11.1 — input/eligibility and policy.** Load canonical fact, approved bindings/source status, valid/knowledge cut, immutable rule/predicate versions, admitted authority/delegation and control decisions. Model scores, card current fields, retrieval order and usage feedback are forbidden deciding inputs. Intended decisions and observed runtime state are separate predicates. Validate same-fact/scope/base graph and acyclicity; unauthorized/external/derived claims cannot override or fabricate a conflict/fence.
2. **CP11.2 — pure ordered reduction.** Eligibility -> approved correction/lifecycle -> base/branch/conflict -> authorized interval/revision ordering. One scalar current or zero for conflict/withdrawn/pending/unknown. Equivalent normalized value corroboration chooses stable representative + equivalent codes, not duplicate current alternatives. Silent structured source update allowed only under exact key + approved monotonic/direct assertion contract; ambiguous text pending. No UUID/timestamp/model tie-break for incomparable competing values.
3. **CP11.3 — concurrency/base semantics.** expected_head+observed_seq checked under org commit fence. Two equally authorized different values from shared observed base create conflict after second committed branch, even with unequal clocks. Writer that saw newer cut but uses obsolete base is stale, not legitimate concurrency. Duplicate same normalized values corroborate; unauthorized lower proposal does not hide human head. Resolution previews bind conflict ID/branches/generation; new branch makes old review stale.
4. **CP11.4 — bitemporal reads and freshness.** Current, as_of_valid, as_known_at and explicit valid_at+knowledge_seq with half-open intervals. Future values scheduled until effective; late observation not known in earlier cut; retroactive correction never backdates recorded time; identity/policy/source versions replay as known then. Current ACL and erasure always apply to old history. Unknown legacy valid time requires explicit recorded-time approximation opt-in. Expired observed value is last-known/unknown, not current.
5. **CP11.5 — immutable reviewed decisions.** Draft/submitted/under_review/approved/rejected/expired/stale/applied/failed events; votes on exact version/digest/evidence/targets/preconditions. Current proposer/reviewer grants, source access, domain authority, expiry and separation-of-duties checked under lock. Approval and authoritative transition atomic; projection may remain pending. Independent approver required for high-risk identity/promotion/correction/policy/erasure, single-user audited exception only when approved. Idempotent votes; CAS prevents double application.
6. **CP11.6 — lifecycle and logical rollback.** Authorized tombstone prevents implicit resurrection; restore requires explicit lifecycle decision. Rollback is a reviewed compensating decision with new ID/code, target historical state, expected current/conflict, rationale and impact manifest; keeps all intervening events. Reject inaccessible/erased/invalid targets. Read-as-of and physical disaster recovery are distinct APIs. Multi-fact application atomic or explicitly staged, never advertise half applied as complete.
7. **CP11.7 — policy activation and workflow ownership.** Immutable manifest/effective sequence, approved activation/rollback, historical reproduction; no semantic flags bypass safety. Route domain review to primary/backup, bounded/dedup queue and escalation; absent steward never auto-approves. Add reason codes and before/after preview accessible only with grants. Integrate M10 CP10.6 and differential random histories against independent interpreter.
