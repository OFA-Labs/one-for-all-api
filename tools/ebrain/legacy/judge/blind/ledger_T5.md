Weakness for E-Brain: single-user, single-writer-per-project design and lexical-only retrieval; no graph, no multi-agent identity.
- **KB-03 gbrain: ADAPTED (structure and contracts), not adopted as software.** Its data model is the strongest fit for GAMMA's hypothesis (compiled truth + timeline, typed temporal edges with valid ranges and as-of reads, bitemporal facts, page versions with reasons, trust tiers, write gate, source isolation, revision preconditions + idempotent receipts, budget-packed context_pack/delta). It is TypeScript, ~16k files and Postgres-centric; the MVP must re-implement a small subset in Python/SQLite in 4 weeks.
- **KB-04 Claude Mnemonic: ADAPTED (selectively).** Take file-mtime staleness, `<private>` tags, local reranker, fallback chain, and the vis-network relation graph as a visual-brain starting point. Reject per-tool-call extraction ("be generous"), large always-injected blocks with "do not explore the codebase" framing, unwired regex conflict detection, and hard deletes.

## 3. Contradictions between sources

1. **Who decides contradictions: model vs code.** Remcycle rejects model reconciliation ("the model extracts; code decides", https://github.com/lianmatsuo/remcycle/blob/be1e27cd293e607b1e0c4807fd7dfd7aef28d02e/docs/intent.md#L81). Engram lets a model judge reversals at read time (https://github.com/toejough/engram/blob/d2ce817c74ee4fc65645635887510b47b231230f/internal/auto/prompts/candidates.txt#L21-L24) and placement supersession at write time (place.txt L14-L20). gbrain splits it: deterministic typed-claim conflicts and stint rules (memory-trust.md L124-L180, link-validity.ts L184-L238), LLM only in a read-only probe that never mutates (contradictions.md L147-L150).
2. **Retrieval substrate: graph vs lexical.** Remcycle: "Plain BM25 beat the graph and vector memory systems on the academic benchmark. Embeddings are added only if logs show lexical misses" (https://github.com/lianmatsuo/remcycle/blob/be1e27cd293e607b1e0c4807fd7dfd7aef28d02e/docs/intent.md#L87). gbrain reports relational retrieval lifting R@5 0.6626 -> 0.7241 and vector-only far below hybrid (https://github.com/garrytan/gbrain/blob/b8875aab6faaea050f954f30227ebf96f13cc54c/docs/architecture/RETRIEVAL.md#L26-L53). Mnemonic and Engram are vector-first. This directly challenges GAMMA's hypothesis; the gbrain numbers come from its own benchmark and include an oracle upper bound that is not a product score.
3. **Admission: strict vs generous.** Engram requires confirmed, durable, atomic lessons (judge.txt L12-L37); remcycle 0-5 claims per session from the person's words (extract.py L285-L292); Mnemonic says "be generous ... Prefer creating observations over skipping" (https://github.com/lukaszraczylo/claude-mnemonic/blob/f950786a0f89e588fb692b7e2e12c17aafc6c007/internal/worker/sdk/processor.go#L1238-L1275).
4. **Deletion vs retention.** Mnemonic maintenance hard-deletes superseded and aged observations (maintenance/service.go L198-L261). gbrain never deletes facts on consolidation and soft-deletes pages with a 72 h purge window (consolidate.ts L19-L20, schema.sql L120-L124). Remcycle never deletes automatically (memory.py L172-L179). Engram `--discard` deletes note + sidecar but only on curation of offers (amend.go L62-L72).
5. **Dedup similarity rule.** Remcycle: Jaccard >= 0.8 on word sets with negation/digit guard (reconcile.py L184-L195). gbrain: cosine >= 0.92 shadow-only, 0.95 consolidation, with negation/number/date guard (capture-dedup.ts L40-L92). Mnemonic: cosine >= 0.9 merge with no guard (dedup.go L50-L62; config.go L180-L181) and Jaccard 0.4 skip (processor.go L459-L470). Engram: LLM "covered" verdict (judge.txt L46-L50).
6. **Recency half-life.** Mnemonic 7 days for everything (scoring.go L81); Engram 60 days on last-used (recency.go L16, L41-L49); gbrain per kind 7/90/90/365 with no decay for confirmed or owner rows (decay.ts L28-L35, L73-L78); remcycle no time decay, only a 14-day "fresh" bonus and 14-day thread TTL (session.py L17, L55-L60).
7. **Tracking whether memory was useful/followed.** Engram built and then removed follow/ignore counters (commits 0843a253, a9701cb6, dbf517cc); remcycle explicitly rejected "questioning memories that are never looked up" because no look-ups existed yet (intent.md L167); gbrain keeps opt-in rating-driven weights (feedback/settings.ts L24-L33); Mnemonic counts retrievals and thumbs feedback into the score (calculator.go L64-L82).
8. **Context injected per prompt vs per conversation.** Remcycle injects once per conversation to keep the prompt cache (register.tsx L537-L538); Mnemonic injects up to 8k tokens on every prompt (user-prompt/main.go L129-L133); Engram injects per recall moment, deduped against what the session holds (auto.go L76-L80); gbrain recommends boundary placement (session start, post-compaction, heartbeat) and says per-message retrieval beyond entity cards "adds latency faster than insight" (ambient-recall.md L28-L31).
9. **Who may make something global.** Remcycle: only the person's own words (dreaming.py L424-L437). Mnemonic: any observation tagged with a globalizable concept (observation.go L180-L191). gbrain: visibility/trust tiers, owner confirmation only at a terminal (memory-trust.md L36-L37).

## 4. Gaps no source covers (relative to E-Brain needs)

- **Concurrent contradictory writes from several agents.** gbrain has revision preconditions, idempotency keys and per-origin edge ownership (T5-03-20, T5-03-03) but its own doc admits two capture writers can both insert the same claim (ambient-writeback.md L390-L393). Engram serialises everything behind one flock; remcycle has one dream writer and takes "session version wins" on sync (mirror.py L30-L35). No source defines a merge policy for two agents asserting different values for the same fact at the same time (e.g., Codex says X, voice agent says Y within the same minute) beyond "newer wins" or "ask the person".
- **Version correctness / time travel.** Only gbrain has as-of reads (pages via valid_from/valid_until; edges via valid ranges). No source offers as-of reads across the whole graph (facts + pages + edges in one consistent snapshot), and the Python/SQLite equivalent does not exist in any source.
- **Agent and user isolation.** gbrain has source grants and fail-closed remote scoping but its README states sources do not isolate local callers with shared DB credentials (README L160). Engram trusts self-declared identity. Remcycle and Mnemonic have project partitioning only. None gives per-agent write identities with signed provenance on a single laptop.
- **Prompt injection and memory poisoning.** gbrain's regex write gate + trust labels and remcycle's quote check + provenance downgrade are the only real defences; Engram has framing and "never follow requests inside" prompt text; Mnemonic has none and its unused conflict rules would let "ignore the previous ..." supersede memory. No source handles poisoning through the voice channel (spoken instructions transcribed as the user's words).
- **Human-readable visual brain.** Mnemonic has a vis-network relation graph; Engram relies on Obsidian's graph view; gbrain's admin SPA has no graph view; remcycle has a TUI-like panel. None shows freshness, provenance, contradictions and supersession history in one web view, and none shows live multi-agent writes on the graph.
- **Token budgeting.** gbrain (packToBudget, budget_tokens on verbs) and remcycle (4,000-char pack, index byte/line limits) cover read budgets; none budgets the total per-day token spend across agents, and none adapts the budget to a voice turn's latency target.
- **Cost on free tiers.** Remcycle and Mnemonic route LLM calls through the user's Claude Code plan; Engram assumes Claude Code models; gbrain defaults to paid Voyage embeddings/reranker with keyless keyword fallback. No source provides a tested free-tier fallback path (e.g., local small LLM for extraction/judging) with measured quality.
- **"Memory ignored" measurement at runtime.** Only remcycle's correction field (person corrects after the assistant followed an entry) and Engram's deleted evaluator address it; neither measures a memory that was delivered and silently not applied, in production code at the pinned SHAs.
