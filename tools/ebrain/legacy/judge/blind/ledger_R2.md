## 1. What each source actually is

**KB-02 Remcycle.** A Python (stdlib-only) `dream` command plus a TypeScript Claude Code mod. Sessions are archived verbatim (human turns and assistant prose, tool output dropped) into one SQLite/FTS5 file at session end; once a day the dream asks a headless Claude Code to propose quoted claims and open threads per unread session, then deterministic code checks every quote, sets provenance from who actually typed it, reconciles claims against a staged copy of Claude Code's memory folder, and gates the copy before accepting it. Sessions are handed a 4,000-char pack of human-endorsed memories and open threads; anything uncertain is queued for a human ruling in a panel.
- Claimed: "reviews previous sessions, identifies stale or contradictory memories, preserves decisions, improves future session context." Found: TRUE and the most rigorous of the four. Staleness: anchors to vanished files are withheld (R2-02-17), threads expire after 14 days (R2-02-13), the review pass questions dated notes (R2-02-15). Contradictions: deterministic authority rules (R2-02-04) plus quote-backed contradiction/duplicate pairs (R2-02-15). Decisions preserved: decisions/preferences can only be replaced by an equal-or-stronger claim, else put to the person; a pre-existing memory is never replaced without a ruling. Review trigger: first session after 20 h (R2-02-26) or `dream run` / `dream review`. Deleted vs archived: nothing is deleted automatically; retired/contested/stale entries move to `withheld/`, history is kept in `entries.json`, and archive deletion is only `dream purge` by the user. Evidence: https://github.com/lianmatsuo/remcycle/blob/be1e27cd293e607b1e0c4807fd7dfd7aef28d02e/src/dream/reconcile.py#L136-L153 and https://github.com/lianmatsuo/remcycle/blob/be1e27cd293e607b1e0c4807fd7dfd7aef28d02e/src/dream/review.py#L42-L93

**KB-01 Engram.** A pure-Go CLI over an Obsidian-compatible zettelkasten vault (`<luhmann>.<date>.<slug>.md` + `.vec.json` sidecars embedded with a bundled MiniLM model), plus six skills and a Claude Code "automatic memory" mod. Per prompt, a Haiku gate decides if it is a recall moment, Sonnet generates phrases and judges candidates (covered/near/evidence/unrelated, newer-reverses-older); after each turn a Sonnet judge writes durable, atomic lessons as notes. Concurrency is a vault-wide flock; multi-vault exchange is a parent/child tree with pending offers curated by an agent.
- Claimed: "self-correcting memory; learns from sessions, identifies memories that are not being followed, evaluates them, fixes memory problems." Found: PARTLY HISTORICAL. "Learns from sessions" is true today (R2-01-07). The "not followed" detector existed in March 2026 (Haiku FOLLOWED/NOT_FOLLOWED/IRRELEVANT verdicts per surfacing, an effectiveness decision tree proposing delete / narrow situation / rewrite action / escalate), but it was deleted on 2026-03-21 and 2026-04-02 and the counters were removed from the format in v3; the pinned code has no follow-rate tracking. What remains: typed supersession, read-time conflict suppression, LastUsed-based recency, invariant checks, a dev-only Python audit that labels outcomes (surfaced-ignored etc.) but never acts, and a roadmap item (#718) for situation-conditioned experience records. Evidence: https://github.com/toejough/engram/commit/a9701cb679517d1fba8bd5486d76ffc8581f6011 and https://github.com/toejough/engram/blob/d2ce817c74ee4fc65645635887510b47b231230f/docs/ROADMAP.md#L168-L185

**KB-03 gbrain.** A very large TypeScript/Bun "brain" (PGLite or Postgres+pgvector) whose canonical store is Markdown in git, exposed through one operations registry as CLI and MCP, with a frozen seven-verb memory protocol. Knowledge is captured as pages (compiled truth + timeline) and facts (`remember` with mandatory provenance, kind, TTL, visibility, valid_from), filed by schema packs into typed pages, linked by zero-LLM auto-link, retrieved by hybrid RRF search, and maintained by an overnight dream cycle with dozens of free/paid phases. It has the most complete trust model (six trust tiers, taint propagation, fail-closed remote callers, per-source isolation) and concurrency model (revisions + durable receipts).
- Claimed: (no description supplied). ## 2. Per-source verdict

- **KB-02 Remcycle: ADOPTED (core lifecycle).** Python, laptop-only, tested, and its "model extracts, code decides" pipeline (quote check → provenance downgrade → deterministic reconcile → staged gate → atomic accept) is the best-evidenced answer to freshness, self-healing and provenance. Must be adapted for multiple agents (it assumes one human + Claude Code, one writer turn) and for a non-Claude LLM with a free fallback.
- **KB-03 gbrain: ADAPTED (protocol, trust, concurrency, retrieval contracts).** Too large and TypeScript/Postgres-bound to adopt as code for a one-developer MVP, but its memory-verb contract, trust tiers with taint, fail-closed source scoping, expected-revision writes, TTL facts, budget-packed context_pack/delta and expire-not-delete semantics are the right specifications to copy into Python.
- **KB-01 Engram: ADAPTED (selected mechanisms).** Keep the lesson-judge rubric, the injection-safe delivery framing, typed supersession, LastUsed recency, embedding-sidecar state and pending-offer + expect-hash for foreign writes. Do not rely on its "self-correcting" claim (removed); its per-prompt Sonnet pipeline is too costly and too slow (2-minute bound) for voice.
- **KB-04 Claude Mnemonic: REJECTED as architecture; a few parts ADAPTED.** Per-tool-call LLM capture, "be generous" extraction, FIFO deletion, LLM-verdict hard deletes and tag-driven global sharing work against retrieval quality and token cost. Worth keeping: file-mtime staleness, the local bi-encoder + cross-encoder stack, the importance-score breakdown, loopback+token auth, and the small MRR eval harness.

## 3. Contradictions between sources

1. **Who resolves a contradiction.** Remcycle: code decides by provenance authority, a model never makes the same/supersedes call (https://github.com/lianmatsuo/remcycle/blob/be1e27cd293e607b1e0c4807fd7dfd7aef28d02e/docs/intent.md#L81). gbrain: a Haiku classifier decides duplicate/supersede/independent after a cosine fast-path (https://github.com/garrytan/gbrain/blob/b8875aab6faaea050f954f30227ebf96f13cc54c/src/core/facts/classify.ts#L1-L20). Engram: Sonnet marks the older candidate `newer` at read time (https://github.com/toejough/engram/blob/d2ce817c74ee4fc65645635887510b47b231230f/internal/auto/prompts/candidates.txt#L21-L24). Mnemonic (dead code): regex, always prefer newer (https://github.com/lukaszraczylo/claude-mnemonic/blob/f950786a0f89e588fb692b7e2e12c17aafc6c007/pkg/models/conflict.go#L188-L197).
2. **Delete vs archive on staleness.** Mnemonic hard-deletes when Haiku says INVALID (https://github.com/lukaszraczylo/claude-mnemonic/blob/f950786a0f89e588fb692b7e2e12c17aafc6c007/internal/worker/service.go#L1192-L1201). Remcycle withholds and asks (https://github.com/lianmatsuo/remcycle/blob/be1e27cd293e607b1e0c4807fd7dfd7aef28d02e/src/dream/memory.py#L172-L179). gbrain expires with audit, never deletes, purge owner-only (https://github.com/garrytan/gbrain/blob/b8875aab6faaea050f954f30227ebf96f13cc54c/docs/protocol/MEMORY_VERBS_v1.md#L791-L829).
3. **Capture threshold.** Mnemonic: "be generous, not restrictive" per tool call (https://github.com/lukaszraczylo/claude-mnemonic/blob/f950786a0f89e588fb692b7e2e12c17aafc6c007/internal/worker/sdk/processor.go#L1238-L1243). Remcycle: 0-5 claims per session, only what the person said and the repo cannot tell (https://github.com/lianmatsuo/remcycle/blob/be1e27cd293e607b1e0c4807fd7dfd7aef28d02e/src/dream/extract.py#L283-L292). Engram: durable + atomic, excludes status/plans (https://github.com/toejough/engram/blob/d2ce817c74ee4fc65645635887510b47b231230f/internal/auto/prompts/judge.txt#L31-L37).
4. **Retrieval timing.** Engram and Mnemonic retrieve on every prompt (Engram with an LLM gate). gbrain says per-message retrieval beyond entity cards "adds latency faster than insight" and retrieves at session boundaries (https://github.com/garrytan/gbrain/blob/b8875aab6faaea050f954f30227ebf96f13cc54c/docs/guides/ambient-recall.md#L28-L31). Remcycle injects once per conversation and leaves the rest to a recall tool.
5. **Lexical vs vector.** Remcycle: BM25 first, embeddings only after logged misses (https://github.com/lianmatsuo/remcycle/blob/be1e27cd293e607b1e0c4807fd7dfd7aef28d02e/docs/intent.md#L87). Engram: vector-only (MiniLM) with clustering. Mnemonic: vector first, FTS fallback, cross-encoder. gbrain: RRF of both, keyword-only when keyless.
6. **Recency half-life.** Engram 60 days, decaying from LastUsed (https://github.com/toejough/engram/blob/d2ce817c74ee4fc65645635887510b47b231230f/internal/cli/recency.go#L15-L48); Mnemonic 7 days from creation (https://github.com/lukaszraczylo/claude-mnemonic/blob/f950786a0f89e588fb692b7e2e12c17aafc6c007/pkg/models/scoring.go#L81); Remcycle has no decay, only need count plus a 14-day freshness bump (https://github.com/lianmatsuo/remcycle/blob/be1e27cd293e607b1e0c4807fd7dfd7aef28d02e/src/dream/session.py#L57-L60).
7. **Cross-project/global sharing.** Remcycle: only human-provenance claims go global (R2-02-27). Mnemonic: any LLM-chosen tag like `architecture` makes it global (R2-04-17). gbrain: world visibility is the default for facts, private only on request (R2-03-02).
8. **Usage-based self-correction.** Engram built then removed per-surfacing follow tracking (R2-01-01..04); Remcycle explicitly declined to question never-looked-up memories (R2-02-33); Mnemonic boosts score by retrieval count (R2-04-05), i.e. rewards being retrieved, not being useful.

## 4. Gaps no source covers (relative to E-Brain needs)

- **Concurrent contradictory writes from several agents of different kinds.** All four assume one human with one or more coding agents of the same kind. Remcycle serializes with one lock and treats agent-to-agent prompts as non-human; gbrain has revisions and per-client cursors but no rule for "Codex and the voice agent wrote opposite facts within seconds". No source ranks agent types by authority or merges simultaneous writes beyond last-revision-wins / pending queue.
- **Version correctness / time travel.** Partial only: Remcycle and gbrain keep git history and gbrain has `valid_from`/`valid_until` + `--asof`, but `delta` replay returns current versions, not historical ones (gbrain ambient-recall.md L156-L157), and no source answers "what did agent X know at time T" as a first-class query.
- **Agent and user isolation.** gbrain has source grants and trust floors; the others isolate by project path only. None isolates per agent within one user (e.g. voice agent must not read Codex's private scratch) as a designed policy.
- **Prompt injection and memory poisoning.** Best coverage: gbrain trust tiers + taint, Engram "data not instructions" framing, Remcycle quote check + author classification. Missing everywhere: a test corpus of poisoning attacks, and detection of instruction-like content already stored (gbrain mentions "flagged (instruction-like, unconfirmed)" rows in tier.ts L86-L88 but I did not trace the detector).
- **Voice-specific memory.** No source handles ASR errors, spoken (unshaped) secrets, speaker identity in voice, or sub-second retrieval budgets; Engram's liveness bound is 2 minutes.
- **Human-readable visual brain.** Mnemonic has a Vue dashboard and a relation-graph component fed by a graph that is not written; Remcycle has a panel (questions, memories, threads); gbrain has an admin SPA with SVG charts; Engram relies on Obsidian's graph view. None offers a browsable map of memories with provenance, freshness and contradictions in one view.
- **Token budgeting across agents.** gbrain budgets per call, Remcycle per pack and index, Mnemonic per hook; none budgets a user's total memory-injection tokens across several agents or adapts to each agent's context size.
- **Cost on free tiers.** Remcycle and Mnemonic spend the user's Claude plan through Claude Code; Engram calls Haiku+Sonnet per prompt; gbrain's paid phases need API keys. No source provides a free-model fallback path or a per-day spend cap tied to a free tier (gbrain has spend controls docs, not read in depth).
